# Contributing to Open Dictionary

Use the parent repository’s issue and pull request workflow. Include an example headword and link to the source entry for any lexical issue. For a proposed match between senses, include both source IDs or permalinks, the sense boundary you reviewed, and your evidence for equivalence or disagreement.

Keep code and dataset updates reviewable. A data change should name the exact upstream release, checksum, selection, and license. Commit a compact, attributed fixture only when a regression requires one. Keep full exports outside Git.

Use the [testing instructions](docs/TESTING.md) to reproduce a change. Include actual test results for any claim about speed, coverage, accessibility, or offline support.
